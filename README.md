# RWKE-Training

> **一句话定位**：RWKE 引擎的「训练—评估—迭代」侧快照——LoRA 微调、无人值守自主训练、六维人设一致性评分器、注入策略定量对比，以及 `_研究_提速` 的推导提速原型；**附带作者本机真实跑出来的实验落盘结果（`results/`，未修饰、含未达标项）**。

---

## 0. 这个仓库是什么，不是什么

**是什么**

- **训练代码**：`微调.py`（LoRA 微调）、`自主训练.py`（数据→训练→评估→调参的无人值守闭环驱动器）、`认证_微调.py`（裸基座 vs 挂适配器的对比认证）、`训练数据.py`（从打标语料构建训练/评估资产）、`语料纠错.py`（ASR 同音归一化与清洗）。
- **评估器**：`一致性评估.py`——**确定性、零随机**的六维规则化评分器（锚点命中率 / 口癖率 / 五维人设符合度 / 情感基调匹配 / 身份一致性 / 流畅性守卫），是训练闭环里唯一的「裁判」。
- **一组可复现实验脚本**：`测试_*.py`（环境自检、状态接口、冒烟、多模型认证对比、注入策略、连续对话、一致性正负样本、微调冒烟）。
- **真实结果档案**：`results/` 里是 50 个 JSON/JSONL/LOG 实验落盘文件（认证分片、100 轮对话抽检、注入策略扫描、微调轮次、科研身份记忆实验等），`适配器/` 里只有**训练摘要 JSON**，没有权重。
- **提速研究原型**：`_研究_提速/` 下的 profile、双加速、CUDA Graph、单步分歧调试脚本与日志。

**不是什么**

- **不是权重仓库**：没有任何 `.pt` / `.pth` / `.safetensors`；LoRA 适配器权重不入库（体积原因），只留训练摘要。
- **不是全量语料仓库**：`训练数据/`（全量日记、训练集 JSONL）已整体排除（隐私 + 体积），需要用 `训练数据.py` 从自有打标语料重建。
- **不是达标报告**：六维达标线 95 **未达成**，最佳合成分 54.0；本仓库把差距如实写在「诚实边界」里，不做美化。
- **不是通用训练框架**：所有脚本都绑定了 RWKE 的模型矩阵、State 通道与角色资产格式，换项目需要改配置。

## 2. 核心配置与实测读数

### 2.1 训练配置（来自 `系统配置.json` 的「微调」节，原样沿用）

| 项 | 值 |
|---|---|
| LoRA rank / alpha | 8 / 16 |
| 学习率档位 | 2e-4 → 1e-4 → 5e-5（自主训练自动降档） |
| batch / 梯度累积 / 序列长度 | 1 / 4 / 512 |
| epoch 上限 | 3 |
| 六维权重 | 锚点命中率 0.25、口癖率 0.10、五维人设 0.20、情感基调 0.15、身份一致性 0.15、流畅性守卫 0.15 |
| 一致性达标线 | **95.0**（合成分） |
| 迭代预算 | 续训 2 轮 + lr 降档 2 次 + 数据扩充 1 轮 |
| 基座默认 / 主力 | RWKV7-World-0.4B / RWKV7-G1-1.5B |

### 2.2 认证结果（真实、不美化）

| 模型 | 裸基座 | 挂适配器 | 差值 | 达标线 | 结论 |
|---|---|---|---|---|---|
| RWKV7-G1-1.5B | 37.1 | **54.0** | +16.9 | 95 | **未达标**（差 41.0） |
| RWKV7-World-0.4B | 35.1 | **42.6** | +7.5 | 95 | **未达标**（差 52.4） |

逐维 before → after（G1-1.5B）：锚点 22.2 → 9.7｜口癖 0.0 → **100.0**｜五维人设 6.1 → 47.5｜情感 20.8 → 26.4｜身份 82.8 → 88.9｜流畅 98.7 → 98.5。

读法：**角色语感维度收益最大**（口癖率从 0 到满分，五维人设大幅上升，AI 腔出戏清零）；**锚点命中率反而下降**——适配器角色化后不再点名词，而裸基座靠复读问题词虚高，这是评分口径与模型行为的错位，报告里已如实标注。

### 2.3 稳定性与长会话（100 轮连续对话抽检）

| 项 | RWKV7-G1-1.5B | RWKV7-World-0.4B |

| 唯一回复率 | 26.0% | 59.0% |

## 3. 怎么跑

> 前置：需要 **RWKE-Engine** 仓 + 已下载的模型矩阵（`models/`）+ 可用的 `训练数据/`（本仓未收录，见第 7 节）。全部命令在仓库根目录执行，Windows / PowerShell 环境。

```powershell
# 0) 依赖与自检（依赖清单见 Engine 仓 requirements.txt）
python 测试_环境自检.py          # 退出码 0 = 就绪；缺 nvcc/模型会列出来

# 1) 构建训练资产（需自备打标语料；本仓不含语料）
python 训练数据.py               # 生成 训练数据/ 下的训练集、验证集、评估集、日记精选
python 语料纠错.py --扫描        # 语料清洗与同音归一化（可选）

# 2) 最小闭环：微调冒烟 → 正式微调
python 测试_微调冒烟.py
python 微调.py --模型 RWKV7-World-0.4B
python 微调.py --模型 RWKV7-World-0.4B --合并 适配器/RWKV7-World-0.4B_合并.pth

# 3) 无人值守自主训练（快验模式适合先验证管线，正式训练建议夜间跑满预算）
python 自主训练.py --模型 RWKV7-G1-1.5B
python 自主训练.py --模型 RWKV7-G1-1.5B --恢复      # 挂现有 checkpoint 续训

# 4) 评估与认证
python 一致性评估.py --模型 RWKV7-G1-1.5B
python 认证_微调.py --模型 RWKV7-G1-1.5B

# 5) 认证矩阵 / 注入策略 / 100 轮连聊
python 测试_对比.py --快速
python 测试_注入策略.py --模型 RWKV7-World-1.5B
python 测试_连续对话.py --模型 RWKV7-G1-1.5B --轮数 100
python 测试_连续对话.py --互动                    # 本地互动聊天入口
```

关键事实：

- `测试_对比.py --标定维度 1792` 可做扫描表外维度的 λ/γ/τ 标定并回写 `系统配置.json`；
- `自主训练.py` 的每一步决策（续训 / 降档 / 数据扩充）都由 `系统配置.json` 的「微调」节驱动，报告自动生成到 `docs/微调报告.md`（Engine 仓）；
- 单卡实测约 60~120 s/训练步（1.5B），完整 120 步预算需数十小时离线运行——这正是「未达标」的直接原因之一。

## 4. 与 `01_Transformer架构` 的关系

- 01 的 P1~P6 是 **Transformer 上的注入工程**，已被优化到极限并归档；RWKE 把同一套注入公式搬到 RWKV-7，只换底座（`logits += 质心 @ 投影 × λ` 逐行等价）。
- 因此本仓的**评分口径、六维权重、锚点词表、语料纠错规则**全部继承 01 的方法论（尤其是「锚点回响 / 身份一致性」的评估习惯），但**训练对象从 Transformer 换成了 RWKV LoRA**。
- 01 的 P4（KV 情感共振）依赖注意力缓存，在 RWKV 上**不可直接移植**（无 KV cache），等价物是 State 张量有界变换或采样分布引导——这条结论写在 `RWKE-Research` 的角色一致性报告里。

## 5. 与 `03_AHI`（自我意识体项目）的关系

- AHI 关心「自我意识体」的长时同一性、连续记忆与内生能力，铁律禁 Transformer 复刻、要求确定性可复现；RWKE 的递归底座与之一致。
- 本仓能提供的价值是**可量化的「角色一致性 / 记忆保持」评测方法**（六维评分器 + 100 轮抽检 + 漂移指标），它是 AHI 类项目做「同一性测量」时可借鉴的工程口径。
- 但要明确：**这是 02 的独立工程，AHI 主线没有 import 本仓代码**；两者是并行储备，不是依赖。以 `03_AHI` 内文档为准。

## 7. 诚实边界（请勿跳过）

1. **六维 95 达标线未达成**：最佳 54.0（G1-1.5B），差距 41.0；0.4B 最佳 46.2，差距 52.8。直接原因是训练预算只跑到 20/120 步（`微调报告.md` 有完整五轮实录）。**不要把这个仓当作「角色微调已完成」的证据。**
2. **最低维度是锚点命中率**：适配器上线后锚点命中 22.2 → 9.7 不升反降。诊断是「角色化作答不点名词」与细则口径冲突；提分路径（增补锚点样本、提高锚点权重、加预算）写在报告里，但**尚未验证**。
3. **长会话漂移明显**：G1 前 10 轮 43.0 → 后 10 轮 24.0（-19.0），唯一回复率仅 26%；根源仍是基座复读边界（见 Engine 仓「诚实边界」），不是训练脚本能单独解决的。
4. **注入策略的部分数字不可采信**：1.5B 现行注入 +381% 是 20~30 轮后退化为英文词循环产生的统计噪声；0.4B 现行注入甚至是 -89.4%。**只有长会话可读内容的 +234% 是可信口径**，且「缓和注入」才是推荐配置。
5. **`_研究_提速` 是原型不是成果**：CUDA Graph / 双加速 / 单步分歧调试都停留在脚本与日志层面，**没有合入主引擎，也没有通过全量一致性回归**；仅供做推理提速方向的人参考思路与踩坑记录。
6. **实验环境单一**：全部结果来自单机 RTX 3080 Laptop 16GB、Python 3.10.11、torch 2.6.0+cu124；换硬件后绝对分数与耗时都会变，**相对结论（增益、漂移方向）才可迁移**。
7. **`results/` 是原始落盘快照**：保留了大量未整理的日志与中间 JSON（包括失败/退化样本），这是刻意的——为了让「没达标」可复核，不是为了好看。
8. **快照性质**：脚本里的模型路径、数据路径、角色资产路径均按作者本机写死并已脱敏；换机器需要改 `系统配置.json` 与各脚本默认参数，**不保证一键跑通**。
